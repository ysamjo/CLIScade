# 2026-10-09

## Harness Router gestartet (PID 5907, Port 3000)

Auftrag: „starte den harness router". Nichts lief auf 3000 (lsof leer).

**Ergebnis:** `node server.js` läuft, PID 5907, `*:3000` (LAN
`http://192.168.178.169:3000`). Geprüft über rohen TCP-Socket (siehe unten):
`GET /` → 200, `GET /api/status` → 200, health listet claude, codex, cline,
opencode, agy, qodercli, freebuff, codebuddy, agent.

### Ein Server lässt sich von hier aus nicht mit `nohup … &` starten

Erster Versuch: `zsh -lc 'nohup node server.js >> log 2>&1 & disown'`. Der
Prozess lief, `lsof` zeigte ihn, Log sauber — **und war eine Minute später weg,
ohne Crash-Spur im Log.** Ursache: der Aufrufer räumt am Ende seine
Prozessgruppe ab; `nohup` schützt nur gegen SIGHUP, nicht gegen `kill` auf die
Gruppe.

**Was funktioniert:** über Python starten mit `start_new_session=True` (setsid).
Der Server wird Session-Leader und überlebt. Launcher liegt in
`/tmp/harness-router-start.py` (nach einem Reboot weg, dann neu schreiben):

```python
subprocess.Popen(["/Users/family/.local/bin/node", "server.js"], cwd=REPO,
                 env=umgebung, stdin=subprocess.DEVNULL, stdout=log,
                 stderr=subprocess.STDOUT, start_new_session=True)
```

Falle beim Schreiben des Launchers: `with open(LOG) as log:` und `Popen(...)`
**außerhalb** des Blocks → `ValueError: I/O operation on closed file`. Datei
offen halten oder Popen in den Block ziehen.

### Env beim Start scrubben

Die Agent-Shell hat `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`,
`ANTHROPIC_MODEL`, `CLAUDE_PROJECT_DIR`, `CLAUDE_SESSION_ID`,
`CLAUDE_CODE_MAX_CONTEXT_TOKENS` gesetzt — die gehören der WorkBuddy-Session und
würden sonst an jeden dispatchten Harness durchgereicht. Vor dem Start
entfernen. Der Server holt sich die Gateway-Umbiegung ohnehin selbst aus der
Login-Shell (`[Gateway] Umbiegung aus der Login-Shell: …`). `QODER_*` war nicht
gesetzt (Regel aus `AGENTS.md` trotzdem geprüft: Zähler 0).

### HTTP-Prüfung von hier aus

`curl` scheitert grundsätzlich — die Shell hat `HTTP_PROXY`/`HTTPS_PROXY`
gesetzt, der Broker antwortet auf localhost mit `502` bzw.
`upstream connect failed … os error 61`, auch mit `--noproxy '*'` und auch
außerhalb des Tool-Sandbox. Verlässlich ist ein **roher TCP-Socket in node**:

```bash
node -e "const s=require('net').connect(3000,'127.0.0.1',()=>s.write('GET /api/status HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\n\r\n'));let b='';s.on('data',d=>b+=d);s.on('end',()=>console.log(b))"
```

### Zwei Dinge, die beim Starten zu beachten sind

- **`ps eww` und `ps -p` sind im Sandbox nicht erlaubt** (`operation not
  permitted`) — Prozess-Env lässt sich von hier nicht inspizieren.
- **Vorschau nicht automatisch öffnen.** Ein Browser-Reload der GUI löst jetzt
  den Auto-Start des PTY-Terminals aus (Änderung vom 2026-10-06), Vorauswahl
  ist `freebuff`. Laut `AGENTS.md` kostet eine superseded freebuff-Session die
  einzige aktive des Kontos. Also lieber die URL nennen als sie selbst
  aufzumachen.
